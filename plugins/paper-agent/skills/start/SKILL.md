# 논문 연구 시작

원칙: **논문을 쏟아 붓지 않는다. 핵심 논문을 먼저 정하고, 그 논문들의 인용 관계를 따라 넓힌다.**
목표는 사용자가 확정한 핵심 논문 5~10편과, 거기에 이어진 연관 논문 목록을 받는 것이다.

- 명령: 아래의 `pa` 는 `"${CLAUDE_PLUGIN_ROOT}/bin/pa"` 를 줄인 것이다. Bash 에서는 전체 경로를 따옴표째 쓴다. 처음 실행은 파이썬 패키지 설치로 1~2분 걸린다고 미리 알린다.
- 데이터: 지금 작업 폴더의 `projects/{slug}/` 에 쌓인다.
- 말투: 한국어 존댓말. 질문은 한 번에 2~3개. 쉬운 말로 쓰고, 전문용어는 괄호로 풀어 준다.
- 인자가 `차별화` 면 9번, `재분류` 면 10번만 한다.

## 묶음과 역할
- **묶음**(리뷰·고전·최전선·직결)은 논문의 종류다. 무엇부터 읽을지 정할 때 쓴다.
- **역할**은 그 논문이 사용자의 논문 안에서 맡는 쓰임이다: 이론 앵커 / 방법 선례 / 현상 선례 / 차별화 대상 / 배경.
  - 키논문은 '무엇을'(이론 앵커)과 '어떻게'(방법 선례)가 따로 있다. 이론 앵커가 사용자와 같은 방법을 쓰지 않은 것은 정상이다.
    예: 구두 이론을 시뮬레이션으로 형식화하는 연구라면, 이론 앵커는 시뮬레이션을 쓰지 않은 원전이고 방법 선례는 다른 이론을 형식화한 시뮬레이션 논문이다.
  - 내용과 방법이 둘 다 같은 논문이 있으면 신규성이 없다는 뜻이다. 그런 논문은 차별화 대상으로 두고 차이를 밝힌다.
  - 저장: `pa db.py role --project {slug} --paper ID --role 역할 --content "쓰임·차이 1문장"`. 화면 '읽기' 탭 제목 아래에서도 정한다.
  - 점검: `pa db.py checkup --project {slug}` — 연도 분포, 국내 문헌 수, 이론 앵커·방법 선례·차별화 대상 빈칸.

## 1. 프로젝트
- `ls projects 2>/dev/null` 로 기존 프로젝트를 확인한다. 있으면 이어서 할지 새로 만들지 묻는다.
- 새로 만들 때: 영문 약칭(slug, 소문자·숫자·-)을 정한다. 인자로 받았으면 그것을 쓴다.
  `mkdir -p projects/{slug}` 후 `cp "${CLAUDE_PLUGIN_ROOT}/templates/brief.md" "${CLAUDE_PLUGIN_ROOT}/templates/decisions.md" projects/{slug}/`

## 2. 연구 방향 대화
모르는 것은 넘어간다. 사용자의 말을 그대로 받아 적는다.
1. 어떤 현상이 궁금한지, 왜 궁금한지 (실무 경험, 관찰한 것)
2. 누구를, 어디서 보는지 (대상, 국가·산업, 시기)
3. **핵심 논문** — 이 연구가 기대는 논문, 이미 읽고 좋았던 논문 (제목·저자·DOI 무엇이든). 가장 중요한 질문이다
4. 쓰고 싶은 이론·관점, 연구 유형 (양적 / 질적 / 혼합 / 미정)
5. 목표 저널, 지도교수 지침

대화가 끝나면 **연구 방향 요약** 한 문단을 보여주고 확인받는다. 이 요약이 이후 모든 선정의 기준이다.

## 3. 검색 전략
- 영문 키워드 5~10개: 핵심 개념의 동의어·하위 개념. 앞의 3개는 가장 좁고 정확한 말로 둔다 (직결 논문 판정에 쓰인다). `entrepreneurship` 처럼 넓은 단어 하나만 쓰지 않는다.
- 국문 키워드, 제외 키워드, 검색 연도 범위 (최근 연구용. 고전은 연도 제한 없이 따로 찾는다).
- 표로 보여주고 확인받은 뒤 `projects/{slug}/brief.md` 를 이 형식 그대로 쓴다. 화면의 '연구 주제 설정' 탭과 같은 파일이다.

```
# {연구 주제 한 줄}
- 분야: 
- 주제 씨앗: (영문 키워드, 쉼표 구분)
- 국문 키워드: 
- 제외 키워드: 
- 연도 범위: 2016–2026
- 연구 유형: 
- 대상 저널: 
- 이론 후보: 
- 지도교수 지침: 
- 목표 노트 수: 40
```
- `projects/{slug}/decisions.md` 표에 날짜, 검색 전략, 이유를 한 줄 남긴다.

## 4. 핵심 논문 정하기
- **아는 핵심 논문이 있으면** 아래 find → add.
- **모르거나 3편 미만이면 먼저** `pa suggest.py ask --project {slug}` — Claude 가 연구 주제·대화를 읽고 관찰을 이론 개념으로 번역해 이론 원전·직접 선행연구·인접 분야 연구·방법·측정 네 묶음(분야 제한 없음)을 추천하고, 하나씩 OpenAlex 에서 실제로 있는지 확인한다(확인됨·확인 필요·못 찾음). 결과는 `projects/{slug}/suggest.json`, 화면 '찾기 → 핵심 논문 추가 → Claude 추천'에서 체크해 등록. '확인 필요'는 판·연도·저자가 다르니 사용자에게 짚어준다.
- 보완으로 `pa keypapers.py discover --project {slug}` — 키워드당 50편만 가볍게 검색해, 그 논문들이 공통으로 인용하는 고전과 리뷰 논문을 후보로 낸다. 후보를 표(제목·연도·1저자·저널·후보 인용)로 보여주고 **사용자가 고르게 한다**. 고른 것은 `pa seeds.py add` 또는 화면 '핵심 논문 후보 찾기'에서 등록.
- 이론·방법 일반서(계획행동이론, 공통방법편의 등)는 핵심 논문 후보에서 구분해 알린다. 주제 핵심 논문이 아니다.
- 논문마다 `pa seeds.py find --project {slug} --query "제목 또는 DOI"` → 후보를 표로 보여주고 **사용자가 고르게 한다**. 같은 제목의 단행본 재수록·학회본·SSRN 원고가 섞일 수 있다.
- 고른 것만 `pa seeds.py add --project {slug} --openalex W...`
- `pa seeds.py expand --project {slug}` → 연관 논문 순위. '핵심' 열은 이어진 핵심 논문 수, '검증'은 인용 기록의 신뢰 단계(DB 1곳 → DB 2곳 → 원문 확인 → 사람 확인).
- 핵심 논문이 정해진 뒤에 넓힌다: 이어진 핵심 논문 수가 많을수록 연결이 강하다.
- 순위 상위에서 연구 방향에 맞는 것을 골라 이유와 함께 제시한다. 화면 '찾기 → 핵심 논문에서 찾기'에서 체크해 읽을 목록에 넣도록 안내한다.
- 연관 논문은 아직 검토 전이다. 원문을 받아 '읽기' 탭의 검토 칸에서 사람이 진위를 확인해야 한다고 알린다.

## 5. (참고) 키워드로 넓게 수집 — 사용자가 원할 때만
- `pa fetch_openalex.py search --project {slug}`
- `pa fetch_s2.py search --project {slug}` — 요청 한도로 일부 건너뛰어도 계속한다.
- `.env` 에 `DBPIA_API_KEY` 가 있으면 `pa fetch_dbpia.py search --project {slug}`
- 사용자가 말한 아는 논문: `pa fetch_openalex.py add --project {slug} --query "제목 또는 DOI"`. 찾은 논문의 저자·연도를 보여주고 맞는지 확인받는다. 틀리면 DOI 로 다시 찾는다.
- ★ 논문이 있으면 `pa fetch_openalex.py related --project {slug}`

## 6. 핵심 논문 후보 계산
`pa keypapers.py run --project {slug}` 를 실행하면 네 묶음 후보가 지표와 함께 나온다.
- **후보 인용**: 모은 논문들이 이 논문을 인용한 수. 높으면 이 분야가 기대는 고전이다.
- **핵심 연결**: 이 논문이 고전을 몇 편 인용하는지. 높으면 주제에 맞는 논문이다.
- 고전 후보 중 이론·방법 일반서(계획행동이론, 공통방법편의 등)는 주제 논문과 구분해, 고를 때 이유에 '이론·방법 기반'이라고 적는다.

## 7. 읽을 목록 고르기
- 후보 초록을 읽는다: `sqlite3 projects/{slug}/library.db "select id, year, title, abstract from papers where id in (...)"`
- 연구 방향 요약을 기준으로 묶음별로 고른다. 리뷰 3~5, 고전 5~8, 최전선 4~6, 직결 4~6, 합계 20편 안팎.
- 한 편씩 저장한다: `pa db.py pick --project {slug} --paper ID --tier 리뷰|고전|최전선|직결 --reason "고른 이유 1문장"`
  - 이유에는 이 사용자의 연구와 어떻게 닿는지 쓴다. 예: "가족 배태성 관점. 가족이 창업 동기·자원에 미치는 영향의 이론 근거"
  - 인용수가 높아도 주제와 먼 일반 창업 논문은 고르지 않는다. 초록이 없어 판단이 안 서면 고르지 않는다.
- 확인: `pa db.py reading --project {slug}`
- 역할이 분명한 논문은 같이 정한다(`pa db.py role`). 특히 이론 앵커와 방법 선례는 따로 하나 이상 고른다.

## 8. 사용자에게 보여주기
- 묶음별 표(제목, 연도, 고른 이유)를 대화에 보여준다. 묶음의 뜻을 한 줄씩 덧붙인다.
  - 리뷰: 연구 지형을 한 번에 본다
  - 고전: 이 분야가 기대는 논문
  - 최전선: 최근 3년, 고전을 이어받아 빠르게 인용되는 논문
  - 직결: 내 주제를 직접 다룬 논문
- 다음 순서를 안내한다.
  1. `/paper-agent:open` 으로 화면을 연다.
  2. '찾기' 탭 맨 위 '읽을 목록 제안'에서 체크하고 '읽을 목록에 넣기'를 누른다.
  3. '③ 읽을 목록 원문 받기'를 누른다. 못 받은 원문은 도서관에서 받아 '읽기' 탭에 올린다.
  4. `/paper-agent:analyze` 로 심층 분석을 맡긴다.
- `pa db.py checkup --project {slug}` 결과의 경고를 같이 보여준다. 차별화 대상이 비어 있으면 9번을 권한다.

## 9. 가장 가까운 선행연구 찾기 (인자 `차별화`)
심사자가 "이걸 모르고 썼나"라고 할 논문을 투고 전에 먼저 찾는다. 연구 질문이 거의 같은 논문이 늦게 발견되면 서론과 기여를 다시 써야 한다.
1. brief 의 연구 주제·이론 후보·연구 유형을 읽고, 사용자의 질문을 "무엇(현상·구성개념) × 어떻게(방법) × 어디서(맥락)" 한 줄로 적는다.
2. 세 축을 둘씩 묶어 검색한다(무엇×어떻게, 무엇×어디서, 어떻게×어디서). 중심 구성개념의 동의어·인접 용어도 넣는다.
   `pa seeds.py probe --project {slug} --query "축 두 개의 핵심어" --top 15` — 저장하지 않고 초록까지 보여준다. 국내 축은 국문으로도 찾는다(`pa fetch_dbpia.py`, 키가 있을 때).
3. 후보마다 초록을 읽고 세 축 중 몇 개가 겹치는지 표로 보여준다(제목·연도·저널·겹치는 축·다른 점).
4. 두 축 이상 겹치는 논문을 차별화 대상 후보로 제안하고, 차이 한 문장 초안을 붙인다. 예: "이들은 간극의 네 형태를 제시했지만 피드백·지연은 형식화하지 않았다."
5. 사용자가 고른 것만 등록·저장한다: 없으면 `pa seeds.py add`, 그다음 `pa db.py role --role 차별화 대상 --content "차이 1문장"`.
6. 세 축이 모두 겹치는 논문이 있으면 숨기지 말고 먼저 알린다. 연구 질문을 조정해야 할 수 있다.

## 10. 연구 방향이 바뀐 뒤 다시 나누기 (인자 `재분류`)
연구 유형(예: 정성 → 정량)이나 주제·대상이 바뀌면 읽을 목록의 절반이 바뀔 수 있다.
1. `projects/{slug}/decisions.md` 의 최근 '연구 방향 변경' 줄과 brief 를 읽어 무엇이 바뀌었는지 한 줄로 적는다.
2. 묶음이나 역할이 있는 논문을 읽는다: `pa db.py reading --project {slug}` · `pa db.py checkup --project {slug}`
3. 표 세 개로 보여준다.
   - **남는 것**: 새 방향에서도 쓰이는 논문. 역할이 바뀌면 바뀐 역할을 적는다(예: 방법 템플릿 → 현상 선례).
   - **빠지는 것**: 옛 방향 전용(예: 면접·집단 모형 구축 방법 문헌). 이유 한 줄.
   - **새로 찾을 것**: 새 방향에 필요한데 비어 있는 역할(대개 방법 선례·차별화 대상)과 찾을 검색어.
4. 사용자가 확인한 것만 반영한다: 빠지는 것은 `pa db.py unpick` · `pa db.py role --role 없음`, 역할 변경은 `pa db.py role`.
   읽은 기록(노트·메모)은 지우지 않는다.
5. decisions.md 에 "재분류: 남김 N · 뺌 N · 찾을 것 N" 한 줄을 남긴다. 새로 찾을 것이 있으면 4번이나 9번으로 이어간다.
